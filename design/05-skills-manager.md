# AI 模块与 Skills 管理器设计

日期：2026-10-09。本文为设计方案，尚未实现业务功能。

## 目标与范围

在左侧导航增加 AI 分组，包含 Skills 管理、AI 服务；后续内置 AI 助手也归入该分组。管理器支持 Codex、OpenCode、Google Antigravity，以及 Project Hub 自己的 AI 模块。Antigravity 首版按 IDE/桌面场景设计，CLI 全局位置单独提供配置。

提供统一的本地技能库，实现导入、内容查看、用途解释、安装到不同工具、检查更新、停用、卸载和导出。全部核心操作在 Electron 主进程执行，不需要服务器。网络仅用于下载、检查更新和用户主动选择的 AI 解读。

关键区别：导入技能库是收藏；安装是把完整技能交付给目标工具；启用是让该目标可以发现或加载；运行是 Agent 根据技能说明执行任务。导入/安装时不自动运行脚本。

## 导航与布局

```text
工作台
  项目总览
  本机服务
  镜像与服务器
  AI 磁盘管家
AI
  Skills 管理
  AI 服务
系统
  全局设置
```

首版将现有 AI 服务表单提取为共用组件，从 AI 分组访问；旧设置入口可以链接到新页面，保留原配置。内置 AI 助手在有实际功能时再出现，避免空页面。AI 磁盘管家保留现有位置。

沿用深色侧栏、靛蓝主色、现有主题变量和 PageHeader。主内容顶部为标题、搜索、来源/目标/状态筛选、扫描本机、导入技能。中部为技能列表和详情区，宽度不足时详情变成抽屉。

列表项显示中文展示名、技术名称、用途摘要、来源、安装目标及异常状态。默认按最近导入排序，支持按名称排序；状态页签为全部、已安装、未安装、待更新。不要用一个总开关代表四个工具的状态。

选中技能后详情区包括：

1. 概览：说明、使用场景、调用示例、来源及版本。
2. 内容：文件树、Markdown 预览、原文；默认打开 SKILL.md，可查看 references、scripts、assets、agents 等文件。
3. 安装位置：四个目标各自的全局/项目范围、路径、状态和启停操作。
4. 更新与历史：上游版本、本地修改、更新差异、备份和恢复记录。

内容浏览对文本提供查看；二进制资源显示类型与大小，不执行。Markdown 禁用 HTML/脚本，外链通过系统浏览器打开，相对资源只能访问技能包内部。

## 导入方式

| 方式 | 用户输入 | 处理 |
| --- | --- | --- |
| GitHub | 仓库链接、目录链接、SKILL.md 文件链接 | 解析仓库与 ref，获取完整技能目录；仓库含多个技能时列出候选并支持多选 |
| 其他网站 | HTTPS ZIP 链接或直接 SKILL.md 链接 | 识别资源类型并下载；普通介绍网页无法作为安装包时提供下载链接输入或本地文件导入 |
| 本地 | 技能文件夹、ZIP、SKILL.md 文件 | 自动定位技能根目录，预览内容，导入副本；单文件引用其他资源时提示资源不完整 |
| 已有技能 | 扫描工具全局目录或选定项目 | 只读发现外部安装，允许纳入管理、复制到技能库或安装到其他目标 |

不能承诺任意第三方网站都支持一键下载：需要可获取的技能包、仓库或文件链接。首版支持公共 GitHub 和 HTTPS ZIP；其他 Git 托管平台按适配器扩展。私有仓库后续复用 Git 身份验证，不在 URL 中保存 token。

扫描插件提供的技能可只读展示来源，不直接修改插件缓存；插件组件如 MCP、钩子不能当成普通 skill 自动安装。

导入流程：

```text
选择来源 → 下载/扫描 → 识别并选择技能 → 查看说明与文件
  → 加入技能库 / 选择目标与范围 → 冲突处理 → 安装 → 结果
```

目标可以多选。每个目标独立选择全局或指定项目，不依赖侧栏的工作区选择隐式猜测。安装预览给出实际路径、技能数量及冲突。部分目标失败时显示逐项结果，可重试失败项。

GitHub 的分支名可能含斜线，解析 tree/blob 链接不能靠简单固定切段；先核实 ref 或允许用户选 ref 和目录。下载锁定本次解析到的提交，目录链接和原始 SKILL.md 链接尽量追溯到完整包。任意单文件 URL 无法推断辅助文件时只标注为单文件包。

## 工具适配

每个工具有独立适配器：探测安装位置、读取配置、检查格式、安装、启停、卸载、说明刷新方式。保留原始 SKILL.md 和资源文件，不为了通用安装自动改写说明。配置路径允许用户修正。

截至本次设计，官方规则与本机环境线索如下；实现和安装时需要结合实际版本复核：

| 目标 | 全局位置 | 项目位置/生效方式 |
| --- | --- | --- |
| Codex | 当前官方本地发现路径为 ~/.agents/skills；本机会话已有 ~/.codex/skills，需兼容现有安装与 CODEX_HOME | 项目 .agents/skills；根据版本探测。官方支持 skills.config 启停，配置改变后提示重启 |
| OpenCode | ~/.config/opencode/skills，另支持共享 .agents/skills 等目录 | 项目 .opencode/skills 或共享 .agents/skills；权限配置与当前会话刷新按版本处理 |
| Antigravity IDE/桌面 | ~/.gemini/config/skills，兼容旧 ~/.gemini/antigravity/skills | 项目 .agents/skills，兼容旧 .agent/skills；CLI 使用单独全局路径 |
| Project Hub AI | 应用 userData 下的管理库，不需要再复制一份 | 全局可用技能 + 指定项目关联 + 会话显式选择，由应用自己的加载器生效 |

工具之间会扫描共享目录，因此文件安装记录不能与工具一一对应。一个真实路径只建立一个部署记录，再关联能发现它的工具。UI 必须说明“此位置同时被其他工具使用”，不能将删除共享目录当成仅卸载某个工具。

优先使用可验证的原生启停机制；缺乏原生支持时，只能将本管理器拥有的安装移入未被扫描的备份目录停用。外部/插件安装默认只读，不静默挪动、删除或改写。已写入文件和目标已发现分开显示，无法查询目标发现状态时显示“已安装，待目标刷新”，不能假装已生效。

兼容性分三层展示：格式可安装、依赖是否满足、目标是否验证过。包含 Codex 专用工具调用的技能，即使能放进 OpenCode/Antigravity 目录，也不能宣称完整兼容。缺失 CLI、MCP 或模型能力时显示原因和处理建议。

## 用途解释

无需模型时读取 description 和正文，显示作者描述、原文和标签，作为默认可用信息。

“AI 解读”由用户主动触发，复用现有 AI 服务配置。第一次使用清楚展示接收内容的模型服务；默认只发送当前 SKILL.md，附加脚本或引用文件需显式选取。没有模型配置时提供配置入口，不影响导入与查看。

解读输出固定为：解决什么问题、适合/不适合的场景、怎么调用、所需工具、可能涉及的文件/网络/命令操作，并引用原文段落或文件路径。标明这是模型解读，不能保证执行正确或安全。第三方内容作为待分析文本，不将其指令传入执行流程。

缓存键包含技能内容摘要、模型和解读版本；内容变化后使缓存失效。用户自写备注和标签独立保存，不改作者文件。

## 更新、停用与卸载

- 更新：有上游且跟踪分支/标签的包可手动检查；固定提交显示“已锁定版本”，不自动漂移；本地来源通过重新导入更新。
- 更新前展示变更文件及文本 diff。目标目录有本地修改时禁止无提示覆盖，提供保留、备份后替换、另存变体。
- 同名不同来源视为不同库条目；安装到同一目录则是冲突，提供跳过或备份后替换。重命名必须满足目标的名称规则，不能只改文件夹造成 name 不匹配。
- 停用仅改变选定工具/范围的可发现状态，保留技能库。共享目录按工具原生配置单独停用，无法分离时明确影响范围。
- 卸载移除选定的管理器部署，不删除库条目。外部目录未纳入管理时只提供“移除关联”，不冒充实际卸载。
- 删除库条目单独操作，列出关联安装和备份；仍有有效安装时先处理关联，不留下破损路径。
- 导出完整技能目录 ZIP，默认排除本管理器元数据、缓存、凭据与用户记录，保留作者许可证。

## Project Hub 内置 AI 接入

当前 electron/services/ai.service.ts 支持模型服务调用和 OpenCode CLI，不能把“已收藏技能”直接等同于内置 AI 已会执行技能。

内置 AI 分两层接入，但四个目标都在首版管理模型中存在：

1. 技能加载：建立可用技能目录，按全局/项目/会话筛选，默认只提供名称和描述；显式选择或确定使用后读取正文和引用文件。界面显示本次实际加载的技能。
2. 工具执行：由 Agent/工具层提供读取项目文件、执行命令、Git 和已有项目操作，技能只提供流程指导；现有模型 chat 接口不能独自承担这些动作。

Project Hub AI 的使用入口包括：全局 AI 助手、项目详情的 AI 面板、已有 AI 操作（按功能配置允许的技能）。项目页面可选择本次技能，不必从技能管理器跳回查找。

内置运行方式支持直接模型 API 和 OpenCode 等 Agent 后端。委托 OpenCode 时尊重其目录发现和权限体系，不重复注入同一技能；直接模型调用则由 Project Hub 控制技能上下文和工具调用循环。Codex/Antigravity 的目录安装适配不自动等于可将它们作为会话执行后端。

仅支持解释类任务的运行器显示“可加载说明”；缺少工具的执行类技能显示“缺少执行能力”。例如 github-release-desktop 可先解读和准备发布说明；实际构建和上传需要命令执行、GitHub 访问和用户授权。目标 API、MCP、CLI 名称不可用时不要虚构调用。

安装时不执行包内脚本。执行时沿用应用的操作权限，技能文字不能扩大权限。发布、推送、删除等动作呈现具体执行内容及影响范围；日志记录技能修订、工作目录、调用工具和结果。已有授权应复用，不让每一步重复确认。

## 存储与代码组织

独立管理库放在应用 userData，而不是某一个工具的目录。原始修订不可变，安装使用完整副本，避免符号链接权限和平台差异；共享目标目录去重。

```text
userData/skills/
  packages/<package-id>/<revision>/   完整源包
  staging/                           下载与识别临时文件
  backups/<deployment-id>/           更新、停用备份
```

SQLite 建议实体：skill_package（名称、描述、标签）、skill_source（URL/ref/目录/来源类型）、skill_revision（提交/摘要/文件清单）、skill_deployment（真实路径、范围、项目、所有权、状态）、skill_target_binding（部署与目标关联）、skill_analysis（解读缓存）、skill_operation（操作历史）。技能修订、来源和同名变体不能只用 name 标识。

建议增加：

- src/views/Skills.vue 与 AiServices.vue；独立详情、导入、目标位置组件。
- src/types/skills.ts、src/stores/skills.ts；preload 暴露 skills API。
- electron/ipc/skills.ts；skills.service、skills-source、skills-store、skills-targets、skills-analysis 等服务按实际复杂度拆分。
- 内置 Agent 的 skills-loader 与工具执行层独立于安装管理器；项目关系使用 project_id，不复用工作区作为项目路径。

所有路径和下载由主进程处理。导入时限制压缩包大小、解压大小和文件数，拒绝目录穿越及越界链接，校验解压后的真实目标位置；下载 URL 和每次重定向重新校验，公共导入不访问本机、内网或云元数据地址。安装分阶段写入并原子替换，失败恢复；同一目标串行操作。

## 首版交付与后续

首版同时建立四个目标的管理支持：导航、现有技能扫描、公共 GitHub/HTTPS ZIP/本地导入、完整内容浏览、用途解读、全局/项目安装、兼容性提示、启停/卸载、手动更新与备份、导出，以及 Project Hub AI 技能关联和加载接口。

Project Hub 内置 AI 是否能实际运行执行类技能，以工具运行器交付为准：首版可以加载与解释；用户要求在应用内直接构建发布等动作时必须同步交付执行层，不能以“已安装”代替功能完成。

后续增加私有仓库、其他 Git 托管平台、自写技能编辑器、来源订阅、批量更新、正式 AI 会话工作台和运行历史。第一版不实现公共商城搜索和自动运行来源提供的安装命令。

验收场景：

1. 扫描本机发现 github-release-desktop，可阅读所有引用文件，重复导入不会复制覆盖自身。
2. 仓库包含多个技能时可选择其中两个；只安装完整选中目录，并记录提交。
3. 一个技能可关联四个目标，跨工具的共享路径显示真实影响范围。
4. 项目安装与全局安装独立；切换项目只加载该项目有效的技能。
5. 缺少依赖、外部修改、网络失败、冲突、异常压缩包都有明确结果；失败不损坏原安装。
6. 不配置 AI 仍可导入、安装和浏览；解读请求和安装流程互不依赖。
7. 内置 AI 显示本次加载技能与执行能力，不把模型生成的命令自动当成已执行。
8. 本次操作不触及其他项目、外部技能目录或插件缓存的无关文件。
