# AI 资料库

## 使用

重启 Project Hub，在侧边栏「AI → AI 资料库」进入。

- 收藏链接：支持文章、公开 GitHub 仓库，以及工具、Skill、MCP 的文档链接。仓库自动识别为 GitHub；其他类型可手动指定。同一链接去除跟踪参数和锚点后去重。
- 粘贴文字：保存文章、说明或自己的文本。
- 导入文件：支持 5MB 内 UTF-8 Markdown、TXT、HTML、JSON、YAML。HTML 提取正文，原始文件内容同时保留。PDF、Word、视频暂未支持。
- 收藏时填写目的、标签、关联项目，可选择自动分析、自动同步原文。
- AI 分析使用「全局设置 → AI 服务 → 通用 AI」。未配置或失败时收藏和原文仍保留，可在详情里重新分析。
- RAGFlow 使用「全局设置 → 知识库」的连接。配置后收藏默认勾选自动同步，也可以关闭。只上传原文与来源信息，AI 分析和个人笔记保留在本机。

详情提供 AI 整理、原文与来源、我的笔记与项目、资料问答、入库记录。可以选择原文和分析的历史版本，重新获取、补充正文、重新分析、导出 Markdown、归档与恢复。问答回复是临时结果，可加入笔记草稿后保存。关闭详情时有未保存编辑会提示。

列表搜索覆盖标题、标签、笔记、原文快照和 AI 分析，支持类型、阅读状态、处理状态、项目筛选。项目详情的「项目资料」按钮进入该项目的资料列表；从该列表收藏时自动关联项目。

## 保存与处理

资料、来源快照、分析历史、入库记录存放在现有本机 SQLite 数据库的独立 library_* 表。原文按内容哈希与版本去重；重新获取和分析不会覆盖笔记或阅读状态。归档只隐藏本地记录，不删除原文，也不删除远端文档。

后台队列同时处理最多 2 份资料。应用退出后，尚未开始的任务按保存的操作恢复；进行中的抓取、分析和上传显示中断，保留已完成部分，允许重试。问答不执行来源内的命令，本机 OpenCode 调用使用既有只读模式。

文章采用 Readability 提取正文，保留标题、作者、来源与 HTML 快照；不运行网页脚本、不自动载入图片。微信公众号优先读取文章正文区域，并区分微信访问验证页面。遇到登录、验证或脚本加载，在详情点击「浏览器获取」，在独立的内置浏览器中手动完成验证，看到正文后点击「保存当前文章」，也可以手动补充正文。浏览器保留独立会话，不具有本机文件或应用接口权限；网页快照保存后继续按资料设置分析和入库。仓库使用公开 GitHub API，README 和最多 3 份相对链接的 Markdown 文档固定到同一提交；不抓取完整代码库。公开 API 限额或私有仓库会提示手动补充。原文抓取最长 25 秒、5MB；AI 单次提供前 60000 字符，超过时明确标示，完整原文保留。

RAGFlow 文档使用稳定文件名，上传前查找已上传文档，上传成功立即保存 ID，解析失败重试复用该 ID。相同原文的已完成/解析中任务不重复提交；新的原文版本保留独立入库记录。目标服务/知识库发生变化时新建对应记录，历史目标保留。

使用普通分块知识库的 chunks 接口，检测到文档 pipeline_id 时使用 ingest 接口。上传后显示「解析中」，只有文档状态 DONE/3 才显示「可检索」。每 15 秒检查解析中任务，支持手动刷新；临时网络错误保留待解析状态。无法验证目标时不会标记成功。

## 验证

- `npm run test:startup`（分别直接加载开发模式和生产模式的实际构建产物，验证主进程启动与文章解析（含 canvas 标签），避免依赖被测试重新打包后掩盖运行时兼容问题）
- `npm run typecheck`
- `npm run build`
- `npm run test:library`
- `node tests/run-electron-library-smoke.cjs`（先构建）

纯逻辑测试覆盖正文提取、链接规范化、GitHub 提交一致性、大小限制和分析模板。Electron 集成测试使用隔离临时数据库、模拟 AI/RAGFlow，覆盖收藏、原文版本、分析历史、笔记保护、全文搜索、项目关联、失败重试、文件导入导出、持久化、界面收藏和笔记编辑。测试不会写入真实知识库。
