# GitHub Releases 安装包分发

交付可下载的桌面安装包、版本说明和 SHA-256 校验文件，并明确对应的源码版本。默认用中文交流，沿用项目已有工具、平台和版本约定。

## 确定任务边界

- 创建技能、询问发布方法或仅要求构建，不等于授权上传安装包、推送代码或公开发布。
- 用户已明确要求发布到指定仓库时，完成构建和校验后继续发布，不重复索要同一授权。要求草稿时保持草稿；要求准备发布时先完成本地产物和发布说明。
- 未指定平台时，根据当前主机和已有配置选择平台并说明假设，不默认构建全部平台。
- 不默认增加自动更新、服务器后端、Docker、代码签名购买或 GitHub Actions。用户要求自动发布时才配置 CI。

## 检查项目与目标

读取适用的 AGENTS.md、package.json、锁文件、打包配置和已有 CI。检查 Git 状态、当前提交、远程地址、既有标签及目标 Release。

确定以下信息，能从代码和会话推断的不要再问：

- 平台、架构、安装包类型、版本号和标签。
- 应用源码仓库，以及目标下载仓库的可见性。私有源码可以配合单独的公开下载仓库；创建该仓库需要用户授权。
- 产物目录和构建命令；仅有前端构建命令时，需要补上桌面打包。

优先使用已连接且支持 Releases 的 GitHub 工具，否则使用 GitHub CLI。CLI 路径先检查 gh 是否存在、gh auth status 是否通过，再用 gh repo view 验证目标。命令显式指定 --repo，避免误发到另一个远程仓库。不要显示 token 或读取凭据正文。

工具不可用时继续准备本地文件；提供 GitHub 网页上传步骤，准确报告尚未上传。不要自动安装 CLI 或发起登录。

## 构建与本地验证

Electron 项目读取 [references/electron.md](references/electron.md)。其他桌面框架沿用其构建系统，GitHub 发布步骤相同。

- 保留依赖锁文件；不为打包顺手升级框架。新增打包配置时使用稳定应用标识、明确文件范围和独立产物目录。
- 本地构建禁用打包工具的自动发布，将上传作为单独一步执行。
- 运行项目适用的类型检查、构建及必要验证。区分“源码构建通过”“安装包生成”“安装启动验证”，不要将其中一项说成全部完成。
- 从本次构建的输出确认产物，创建显式文件清单。不要用发布目录中的宽泛通配符混入旧版本。
- 检查实际打包内容和构建资源，排除用户数据库、日志、私钥、token、.env 和无关本地文件。安装包不附带发布者个人运行数据。
- 对本次交付的安装包生成 SHA256SUMS.txt，每行格式为 `SHA256  文件名`。记录产物名称、大小、架构和验证结果。
- Electron 原生模块需为目标系统、目标架构和 Electron ABI 编译；只有 TypeScript 构建成功不足以证明安装包可运行。

## 源码对应关系

发布源码仓库时，标签必须指向构建对应的提交。检查工作区是否有进入安装包的未提交修改；不要把含这些修改的安装包宣称为现有标签的构建。按用户授权提交所需改动，或先交付本地候选包并说明未完成正式发布的原因。

创建或推送标签属于发布任务的一部分，但不要自动推送无关改动。既有标签不移动、不强制覆盖；版本冲突时核对已有 Release，或确定新版本。

独立下载仓库的标签不代表应用源码版本；在发布说明记录应用源码提交和构建来源，私有仓库信息按用户公开范围处理。

## 发布到 GitHub

先准备完整发布说明，包含版本、平台/架构、安装方式、实际变更和已知限制。只写已验证事实，版本历史不可用时不要编造更新记录。多行正文保存为 UTF-8 文件，通过结构化工具参数或 gh --notes-file 传入。

源码仓库已有远程标签时，使用 gh release create 的 --verify-tag；不要让 CLI 默认从远程默认分支生成错误的标签。新标签先对构建提交创建并推送。独立下载仓库则明确使用该仓库的已核实目标提交，避免引用其不存在的应用源码提交。

命令形态如下，所有变量需从实际任务确定，$releaseAssets 为显式文件路径数组：

```powershell
gh release create $releaseTag @releaseAssets --repo $releaseRepo --verify-tag --title $releaseTitle --notes-file $releaseNotes
```

用户要求草稿时加 --draft；预发布加 --prerelease 并避免将其设成稳定版最新版本。不要自行把准备发布升级为正式发布。

同一标签已有 Release 时先检查状态和附件：保留用户已有内容，只补充本次需要的文件。同名文件已存在则核对内容，不默认 --clobber。失败后先查看远端状态再恢复，避免重复创建；同一权限或版本冲突确认后停止盲目重试。

上传后核对 Release 页面、草稿/预发布状态、标签及附件名称和大小。下载到临时目录并对比本地 SHA-256，验证安装包和校验文件；若工具或网络无法完成下载，明确标注下载校验未完成。私有或草稿链接不能描述为所有人可公开下载。

最终交付安装包本地路径、Release 链接、版本和平台、验证结果，以及实际未完成项。当前请求仅构建时只交付本地产物和说明。
